# 雷电模拟器游戏自动化


通过雷电自带的 ADB 获取 Android 原始画面、模拟点击/滑动/按键，后续每个任务作为独立 Python 脚本增量添加。Daily_Hero 使用真实游戏截图的视觉特征进行判断，支持 16:9 横屏，推荐 **1920×1080**。

## 新电脑从零运行

准备 Windows 10/11、Git、**64 位 Python 3.11 或以上**（安装时勾选加入 PATH），以及雷电模拟器。先在雷电安装游戏、登录账号，在模拟器设置中开启 **ADB 本地连接/本地调试**，设置为 1920×1080 横屏，并启动游戏。不同版本的设置名称可能略有不同。

在 PowerShell 中运行：

```powershell
git clone https://github.com/Real-UtopiaNo/mxm.git
cd mxm
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

初始化会创建本目录的 `.venv`、安装视觉依赖，再检查 ADB、在线设备、所有视觉模板和实际截图；不会向游戏发送点击。默认自动查找 PATH、环境变量、运行中的雷电/ADB、注册表和常见安装位置，并选择唯一在线的设备，无需照搬原电脑的安装目录或设备编号。

将游戏停在**天星镇主页面**，先预演再运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_daily_hero.ps1 -Preview
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_daily_hero.ps1
```

按 **Ctrl+C** 停止。无需激活虚拟环境，也无需管理员权限。更新代码后重新执行 `setup.ps1` 即可安装新增依赖。Python 不在 PATH 时可传入 `setup.ps1 -PythonPath 'D:\Python\python.exe'`；暂时不连接模拟器可用 `setup.ps1 -SkipDeviceCheck`，稍后执行下文的 `doctor`。

仓库包含代码、视觉模板和测试样本；Python、雷电、游戏本体和游戏账号需要在新电脑单独准备。脚本从已有游戏画面开始，不自动安装游戏或登录。

## 使用

以下命令均在 clone 的仓库目录内执行。截图和输入基础功能只使用 Python 标准库；`Daily_Hero` 和环境检查需要 `setup.ps1` 安装的视觉依赖：

```powershell
.\.venv\Scripts\python.exe -m pet_alliance doctor
.\.venv\Scripts\python.exe -m pet_alliance devices
.\.venv\Scripts\python.exe -m pet_alliance capture
.\.venv\Scripts\python.exe -m pet_alliance capture --output artifacts/screenshots/current.png
```

截图默认保存在 `artifacts/screenshots/`，每次生成带时间戳的新 PNG。获取的是游戏内容，不包含模拟器标题栏和工具栏；窗口缩放、移动不会改变截图坐标。

公共默认配置在 [automation.toml](automation.toml)。如果自动发现失败，复制 [automation.local.example.toml](automation.local.example.toml) 为 `automation.local.toml`，填写雷电安装目录中 `adb.exe` 的完整路径。该文件已被 Git 忽略，只覆盖填写的配置项；例如：

```toml
[device]
adb_path = 'D:\leidian\LDPlayer9\adb.exe'
serial = ''
```

`serial` 留空自动选择唯一在线设备。多个实例同时在线时，先执行 `devices` 查看编号，再填写 `serial`，避免操作其他实例。也可单次覆盖：

```powershell
.\.venv\Scripts\python.exe -m pet_alliance --serial emulator-5554 capture
.\.venv\Scripts\python.exe -m pet_alliance --adb 'D:\其他目录\adb.exe' devices
.\run_daily_hero.ps1 -AdbPath 'D:\其他目录\adb.exe' -Serial emulator-5554 -Preview
```

配置优先级是命令行参数 → `automation.local.toml` → `automation.toml`。显式使用 `--config` 时只读取指定的文件；相对路径以该配置文件所在目录为基准。也支持 `ADB_PATH` 指向 ADB，或 `LDPLAYER_HOME` 指向雷电安装目录。

如果设备列表为空，请在雷电设置中开启本地 ADB 调试，并保持模拟器启动；如果设备显示 `offline`，等待启动完成或重启模拟器后重试。若雷电使用 TCP 地址连接，可先运行 `& 'D:\leidian\LDPlayer9\adb.exe' connect 127.0.0.1:5555`，其中端口应使用当前实例实际的 ADB 端口，再执行 `devices`。排查后用 `doctor` 再次确认截图可用。

## 输入操作

坐标以原始截图左上角为 `(0, 0)`，向右增加 x，向下增加 y；1920×1080 截图的范围为 `0 ≤ x < 1920`、`0 ≤ y < 1080`。修改模拟器分辨率或切换横竖屏后，需要重新抓图确认手动坐标。Daily_Hero 会自动映射同为 16:9 的实际分辨率。

```powershell
# 先预演：只打印动作，不发送点击
python -m pet_alliance --dry-run tap 960 540

# 以下命令会实际操作游戏
python -m pet_alliance tap 960 540
python -m pet_alliance swipe 1400 540 500 540 --duration 400
python -m pet_alliance key back
```

## 增量添加任务

在 `scripts/` 新建文件，例如 `daily_task.py`，定义 `run(ctx)`。文件名使用英文字母、数字、下划线，并以字母开头。示例：

```python
from pet_alliance import ScriptContext


def run(ctx: ScriptContext) -> None:
    ctx.screenshot("before")
    ctx.tap(960, 540)
    ctx.wait(1)
    ctx.screenshot("after")
```

```powershell
python -m pet_alliance scripts
python -m pet_alliance run capture_once
python -m pet_alliance --dry-run run daily_task
python -m pet_alliance run daily_task
```

`ctx.capture()` 返回含 `data`（PNG 字节）、`width`、`height` 的对象，可作为后续按钮图像匹配、文字识别和状态判断的输入。`ctx.screenshot()` 保存并返回绝对路径。其他接口包括 `ctx.tap()`、`ctx.swipe()`、`ctx.key()`、`ctx.wait()` 和 `ctx.log`。新视觉任务可以复用 `pet_alliance.vision` 的模板匹配和坐标转换。

`--dry-run` 拦截通过 `ctx.tap/swipe/key` 发出的输入；截图、等待和脚本中的普通 Python 代码仍会执行。任务脚本应通过这些接口操作游戏；直接使用底层 `ctx.device` 会绕过预演。

运行在前台，按 **Ctrl+C** 停止。

## 全天托管调度器

先把游戏停在**天星镇主页面**，再打开面板：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\run_scheduler.ps1
# 或在终端运行：
.\.venv\Scripts\python.exe -m pet_alliance scheduler
```

面板显示启动、暂停、北京时间、当前任务、今日两个英雄任务的完成情况、擂台结束时间和后台日志。打开面板不会连接或操作游戏；点击“启动”后才开始调度。

面板分为“全天托管”和“单任务运行”两页。单任务页自动列出 `scripts/`（或 `automation.scripts_dir` 指定目录）中的脚本，每项都有独立的“启动”“停止”和运行状态：

| 脚本 | 单任务用途 |
| --- | --- |
| `Daily_Hero` | 完成每日英雄副本，沿用每三个副本参加积分赛的规则 |
| `daily_hero_reset` | 重置并重打选定区域，统计钻石消耗 |
| `check_arena` | 检查魔都擂台，必要时完成对应英雄前置再占擂 |
| `slay_dragon` | 运行屠龙托管，保留活动时段判断和恢复流程 |
| `capture_once` | 仅保存一次当前截图，不进行回城或点击 |

“全天托管”和“单任务运行”页各有一个英雄积分赛开关，两个开关共用配置，默认开启。开启时，每完整通关三个英雄副本参加一次积分赛；关闭时，英雄副本、英雄重置及占擂补打英雄均不参加积分赛，正常占擂检查仍照常进行。开关在任务停止后可修改，修改后保存，下次启动生效；默认写入本机覆盖文件，使用 `--config` 时写入指定配置。

命令行使用 `[daily_hero]` 下的 `points_arena_enabled` 配置项，值为 `true` 或 `false`。关闭会清除当天待继续的积分赛和三副本计数，保留已完成副本、今日完成标记与钻石消耗；关闭期间不积累积分赛次数，重新开启后从零计数。

单任务只执行所选脚本，结束后不会自动启动其他任务，也不受全天调度的优先级抢占。业务任务启动前先确认回到天星镇。全天托管与所有单任务共用一个后台执行线程：已有任务运行或正在停止时，其他启动按钮禁用。点击“停止”后立即请求停止后续自动输入，等待已发出的 ADB 调用返回并保存进度；不会为停止额外点击回城。

单独运行英雄任务的完整完成和已确认进度会同步到“今日完成情况”，擂台结果也会同步到全天调度状态。可以手动启动当天已完成的脚本；重复运行中途停止不会撤销原有的今日完成标记。两页共用下方实时日志，单任务运行结果和原有截图记录继续保存。新增脚本放入配置的脚本目录即可被列出；自定义脚本需使用 `ctx` 的输入、等待接口，才能响应停止。

两种运行模式共用配置指定的调度状态文件（默认 `artifacts/scheduler/state.json`），关闭并重新打开面板后仍可接续。单任务英雄/重置未完整完成时会保留已确认的副本、积分赛待处理状态和计数，以及重置钻石明细；之后全天托管继续读取这些进度。单任务占擂无可用目标、且已确认回城时，也会保存与全天托管相同的五分钟重查期限，切换模式或重开窗口不会立即重复检查。屠龙属于按时段反复执行的任务，只保存运行结果，不标记为“今日已完成”。

四项业务任务在启动前自动使用已保存的宠物组：英雄副本和英雄重置使用“刷图”，屠龙使用“屠龙”，占擂使用“PVP”。全天托管、单任务按钮和原命令行脚本均采用此准备流程。流程先确认天星镇，点击顶部第二个宠物图标，再按底部完整组名选择，点击“一键使用”、确认，关闭宠物页并确认回城；按名称寻找，不依赖 A/B/C 的固定位置。确认后仍留在方案预览时先返回宠物页。无法确认任一步就停止当前任务，保留 `artifacts/runs/Pet_Loadout_*/` 中的日志、PNG 和结果；不会带着未知方案继续战斗。截图任务和预演不会进行换组。

占擂需要补打某个英雄副本时，只在确认该副本尚未通关后临时换成“刷图”，重新定位并复核同一副本；战斗正常结束后换回“PVP”，再回魔都检查占擂。暂停或异常时直接保存并停止，不在收尾中额外换组。屠龙仍在运行之初先判断北京时间：休场时先等待，不会提前换组；开场恢复、重启登录后先处理遮挡通知，再重新使用“屠龙”组，换组过程中也会检查时段结束并转入等待。登录通知与屠龙入口仍共用原有五分钟时限。

参数可以放在 `scheduler` 前后，例如：

```powershell
.\.venv\Scripts\python.exe -m pet_alliance scheduler --config 'D:\Game\mxm\automation.toml' --serial emulator-5554
.\run_scheduler.ps1 -AdbPath 'D:\其他目录\adb.exe' -Serial emulator-5554
```

调度器不支持 `--dry-run`，传入会明确报错；各独立脚本仍可按下文方式预演。

优先级为 **魔都擂台 → 屠龙 → 每日英雄副本 → 选定区域的英雄重置副本**：

北京时间每天 **00:00** 先执行一次游戏重启，再登录并确认天星镇，之后才按上述优先级继续。零点到达时先停止当前任务的后续自动输入，保存已经确认的进度，再执行重启；不会先操作旧画面或继续占擂。当天重启完成记录持久化到调度状态，暂停恢复、同日关闭再打开不会重复。暂停跨过零点时保持不操作，恢复后先补一次当天重启；重启或登录失败、尚未完成时暂停，不标记完成，下次恢复再尝试。

登录时循环处理两类通知：带“公告”标题的更新页面点击右上角叉号，原通知点击底部“点击空白处关闭”。两类可以任意顺序连续出现，每次关闭后重新截图判断，全部处理完并确认天星镇后才继续调度。叉号必须同时匹配公告标题，不会点击其他页面的相似叉号；登录按钮和两类通知分别计算补点次数，仍共享该登录处理循环的总超时。

- 未记录擂台结束时间或时间已经到达时，先按 `arena_list` 检查魔都擂台。占无人擂台前必须确认**该副本当天的英雄级五关全部通过**；调度器会在必要时先打通这个具体副本，再重新确认擂台是否仍然无人。不会因此购买重置，也不必先清完所有区域。确认本人新占擂后，以首次挑战点击时间加 **6 小时 1 分钟**记录调度期限，其中一分钟用于等待缓冲。守护到期后游戏自动空出擂台，再按优先级尝试占擂。所有目标均被他人占据、或本轮英雄前置未能通过时，回城并等待 **5 分钟** 后重查；等待期间仍可执行其他任务。
- 屠龙活动时段为北京时间 **09:00–11:00、12:00–16:00、18:00–22:00**，由 `[slay_dragon].start_times` 决定。在此期间托管屠龙；擂台到期时中途回城处理擂台，再继续屠龙。屠龙回城点击左下“天星镇”文字下方的发光环。
- 屠龙休场期间依次执行 `Daily_Hero`、`daily_hero_reset`；当天已完成的任务直接跳过。全部完成后等待下一次擂台到期、屠龙开场或北京零点。原有每完成三个英雄副本参加积分赛的逻辑继续保留；积分赛与这里优先级最高的魔都擂台分别处理。
- 每次切换任务先确认回到天星镇。英雄任务遇到擂台、屠龙等更高优先级任务时，在完成当前整个副本及该副本触发的积分赛往返后切换；屠龙可在监测过程中切换。每日零点重启优先于这些普通任务，会先停止后续输入并保存已确认进度。

点击“暂停”会立即请求停止自动输入，保存已确认的进度；不会为了回城继续点击。已发出的单次 ADB 调用需要先返回。随后可手动玩，准备恢复时先自行回到天星镇，再点击“启动”。关闭窗口同样停止输入，并等待后台保存状态后关闭。暂停期间不会继续执行到期任务；恢复时重新按当前北京时间和优先级判断。

修改 Python 脚本后，需要完全关闭托管窗口，等待退出，再重新运行 `run_scheduler.ps1`。面板中的“暂停 → 启动”只重新读取配置，保留进程中已经加载的 Python 代码，不能加载脚本修复。新版新占擂报告包含 `claimed_at`，确认事件包含 `confirmed_on = "map"`，可用于核对实际执行的流程。

每日状态保存在 `artifacts/scheduler/state.json`，按**北京时间每天零点**切换。只有脚本报告完整完成才标记“今日完成”；暂停、中断、报错或只达到运行限额均不会标记完成。当天重启面板或暂停后恢复，已经完成的每日任务不会再跑。跨过零点才结束的旧任务不会把新一天标记为完成。

为占擂提前打通的英雄副本也会计入当日英雄进度和每三个副本参加积分赛的计数，但不会把整个每日英雄任务标记完成。第三个副本后若在积分赛前或途中暂停，会保存“积分赛待继续”；恢复时先补这次积分赛，再继续正常调度，不会提前把计数清零。占擂资格依据新截图中五关的“击败”印章确认；红点消失、灰色重置按钮或历史完成记录都不能单独作为依据。核验后若跨过北京时间零点，会重新检查目标副本。

部分完成时保留进度和已确认的重置钻石消耗，下次依据游戏实际地图、关卡与按钮状态重新检查：普通英雄副本优先处理仍有标记的目标，重置脚本继续使用已选区域及灰色重置按钮的跳过规则。不会因中断而主动再次购买同一副本的重置；若已重置的副本尚未打完，灰色按钮仍按现有规则跳过。

面板日志同步写入 `artifacts/scheduler/scheduler.log`。运行日志仅保留北京时间当天：打开调度器或运行独立脚本时清理 `artifacts/runs/` 中已过期的运行目录；持续运行和暂停的面板也会在零点自动清理。跨零点的任务会把后续事件、截图和摘要写入当天的新目录，保留已经确认的进度。面板与 `scheduler.log` 只保留当天内容，旧的 `.log.1`～`.log.3` 会在首次打开新版调度器时迁移当天记录并清理。配置、每日完成状态、擂台期限、钻石统计历史及 `artifacts/temp/`、`artifacts/screenshots/` 中的图片继续保留；无法清理的忙碌文件会记录原因并稍后重试。识别失败或设备错误会停止当前调度并显示原因，排查后回到天星镇再启动。不要同时启动另一个独立脚本操作同一模拟器；调度器之间也会检查运行锁，避免重复托管。

## Daily_Hero：每日英雄级副本

已使用真实游戏截图建立 OpenCV 彩色模板库。通过“页面特征 → 区域名称和推荐等级 → 右上角感叹号 → 副本感叹号 → 英雄模式 → 挑战 → 跳过 → 下一关”的视觉判断执行。点击位置由匹配结果计算；模板统一在 1920×1080 下识别，并映射回设备实际分辨率，支持同比例的 16:9 横屏。

仅西部大陆“莫鲁之地”使用第三怪中场退出后续战的特殊流程：命中其专用中场画面后先退出，重新点击同一英雄副本的“挑战”，继续第四、第五怪；中场退出不计入副本完成数，也不触发重置或积分赛。全部关卡结束后才计为一个完整副本。其他副本保持原来的完成与退出逻辑，不会仅因第三次胜利或退出后仍有“挑战”就再次挑战。`daily_hero_reset` 共用莫鲁之地的续战路径，仍保留普通初次进入或普通失败重试遇到灰色重置时跳过的规则。

完成 `setup.ps1` 后，把游戏放在**天星镇主页面**，运行：

```powershell
.\.venv\Scripts\python.exe -m pet_alliance run Daily_Hero
```

也可以使用启动脚本：

```powershell
.\run_daily_hero.ps1
```

脚本也支持从区域地图、大地图或已打开的副本面板开始。预演只判断当前页面，不会假装走完尚未打开的页面。

- 进入“冒险”后先检查当前区域，优先处理带红点/感叹号的副本；从区域图或副本面板启动也采用同样顺序。当前区域没有尚未尝试的目标后，才打开大地图寻找其他红点区域。完成或已按重试上限放弃的副本在本次运行内不再重复处理。
- 天星镇的“冒险”和“竞技场”入口被云遮挡时会持续截图识别，最多等待 **5 分钟**；识别到后才点击，补点也重新识别。英雄脚本启动、积分赛入场和回城均采用这一等待逻辑，其余页面仍使用 `transition_timeout`。
- 大地图选择同时匹配区域名称、推荐等级和感叹号的区域；已处理区域在本次运行内不重复进入。当前区域的红色菱形可能遮住感叹号，其他区域处理后会补查一次该区域的副本标记。
- 区域入口使用匹配结果及该区域的 `click_offset` 计算点击位置；奇幻梦境、异界幻世点击图标，避免落在下方不可点击的推荐等级上。不同区域的偏移可在 `assets/daily_hero/profile.json` 分别调整。
- 区域内只进入带感叹号的副本；感叹号使用内部图像特征匹配，覆盖浅色地图和最右侧入口。聊天预览遮挡弗瑞斯时，结合稳定地标和标记残留颜色补查；完成和放弃的副本在本次运行内不再重复处理。
- 切换后必须同时识别英雄模式龙形标志和“挑战”按钮，才开始战斗。
- 所有导航、挑战、跳过、下一关、退出和领奖均采用“点一次 → 截图确认 → 未生效再补点”。任意两次点击默认至少间隔 **1 秒**；点击后观察 **2 秒**，只有原页面的按钮仍能重新识别时才补点，最多补点 **3 次**。加载中或原按钮已消失时只等待，不沿用旧坐标点击。
- 战斗中看到“跳过”立即点击。结算界面优先于背景战斗界面识别；获胜后继续“下一关”，按钮变灰时退出当前副本，若出现通关奖励则识别并领取。
- 失败后点击“退出战斗”。如果回到英雄面板，直接继续挑战，保留已经打过的关卡；如果返回地图，则重新进入同一副本。**不会把“回放”当成重试。**
- 默认首次挑战之外最多额外重试 **10 次**，即同一副本累计第 **11 次失败**时放弃；计数不因中间打赢某一关而重置，换副本后重新计数。下次运行会重新考虑这些副本。
- 每完整通关 **3 个英雄副本**，通过大地图回天星镇，进入“竞技场 → 积分战 → 自由竞技场”。每次报名使用一张入场券连续挑战 **3 场**，每场跳过并退出战斗；确认三场结果后重新截图读取票数，有票就再次参加，直到显示 **0/5** 才关闭面板并回到原区域。计数跨区域累计，单关胜利和重试耗尽而放弃的副本不计入；即使第 3 个副本恰好达到 `max_dungeons`，也先完成本次积分赛往返。
- 积分赛返回后先进入冒险并核对区域地图背景；仍在原区域时直接续打，保留已处理记录，避免再次绕行大地图。返回了不同地图时，再通过大地图恢复原区域。区域图不显示区域名，因此首次就地处理时暂记“当前区域”，等确实需要打开大地图时再确认并补全报告中的名称。
- 积分赛只选择 `[daily_hero]` 的 `target_players = ["Hello", "Hell", "coco"]` 中的玩家。列表长度不限，每场都从第一项开始按优先级查找，选择当前页面可见且仍可挑战的第一个目标；头像已被结果印章覆盖的卡片会跳过，即使名字仍可见。若该玩家仍可挑战，可以再次选择，每张入场券对应 **3 场**。完整匹配且区分大小写（`Hell` 不会匹配 `Hello`）。玩家可中途加入或换格，最多 **2 行×4 列**；每次挑战和补点都重新扫描全部八格，不将名字绑定到某个格子，也不沿用上轮名单或点击位置。暂无名单目标时只观察，直到 `transition_timeout` 仍无目标才报错并保存现场，绝不选其他玩家。增加新名字需同时采集并登记完整名字模板，见 `assets/points_arena/`。
- 入场券显示 **0/5** 时不参加，直接关闭面板并回原区域；再通关 3 个副本后仍会再次检查。票数无法确认、页面异常或等待超时都会停止。积分赛的导航、报名、确定、选人、跳过、退出战斗、确认结果、关闭和返程均沿用同一套补点逻辑：先点一次，等待确认，只有控件仍能重新识别时才按 `click_retry_interval` 补点，最多 `max_click_retries` 次；加载中或目标消失只观察，不点击旧位置。`min_click_interval`、最长运行时间和 Ctrl+C 停止机制同样生效。
- 未知弹窗、加载卡住、资源不足等导致页面无法识别时停止并保存现场。不会盲点弹窗；Ctrl+C 随时停止。

参数在 `automation.toml` 的 `[daily_hero]` 下：`min_click_interval` 是两次点击的最小间隔（秒），`click_retry_interval` 是点击后确认未生效的观察时间（秒），`max_click_retries` 是单次点击的补点上限。`max_retries` 单独控制战斗失败重试次数；`transition_timeout` 控制页面等待超时；`max_runtime` 控制总运行时长。`max_dungeons = 0` 表示遍历全部未完成副本，设为 `1` 可只处理一个副本。

`points_arena_enabled = true` 保持每三个完整副本参加积分赛；设为 `false` 则跳过，包括暂停前留下的待继续积分赛。此项统一以 `[daily_hero]` 为准，同时控制英雄重置和占擂补打英雄；不使用其他任务配置节中的同名覆盖值。

每次运行生成 `artifacts/runs/Daily_Hero_时间戳/`，包含动作匹配分数、点击位置的 `events.jsonl`、完成/跳过/失败统计的 `summary.json`，以及失败和停止时的截图。`summary.json` 还记录积分赛往返次数 `arena_visits`、累计已结束场数 `arena_battles` 和识别到零票的次数 `arena_no_tickets`；积分赛胜负不影响英雄副本的胜负或重试计数。

积分赛每次准备选人及最终无目标停止时，还会保存对应的无损名单 PNG，例如 `arena_visit_1_entry_2_round_3_select_1.png`、`arena_visit_1_entry_2_round_3_target_missing.png`。这些图片来自作出识别判断的同一帧，不会额外向设备请求截图；不同往返、报名轮次、场次分开保存，避免连续用券时覆盖，便于检查中途加入、换位或细字误识别。

英雄副本逻辑位于 `pet_alliance/daily_hero.py`，积分赛流程及名字/票数识别分别位于 `pet_alliance/points_arena.py`、`pet_alliance/arena_vision.py`。通用视觉模块位于 `pet_alliance/vision.py`，模板及配置分别位于 `assets/daily_hero/`、`assets/points_arena/`。其他任务可复用视觉模块并拥有各自的模板目录。游戏 UI 改版时更新模板及测试截图。

## daily_hero_reset：重置选定区域的英雄级副本

```powershell
.\run_daily_hero_reset.ps1
# 仅检查当前截图，不点击：
.\run_daily_hero_reset.ps1 -Preview
# 或直接运行：
.\.venv\Scripts\python.exe -m pet_alliance run daily_hero_reset
```

在 `automation.toml` 中选择要重置的区域和单独副本：

```toml
[daily_hero_reset]
regions = ["西部大陆", "环形领地", "诅咒荒野"]
dungeons = ["奇幻梦境-龙萌幻境"]
```

脚本先通过大地图核对区域，按 `regions` 顺序处理各区域的全部副本，然后按 `dungeons` 顺序处理指定副本。指定项使用“区域-副本”格式，只点击完整副本名称匹配的入口，不会处理该区域的其他副本；没有识别到目标会报错停止。当前支持“奇幻梦境-龙萌幻境”的真实名称模板，其他名称需先补充对应模板；不支持的名称在开始操作前报错。`dungeons = []` 只按区域处理；`regions = []` 且 `dungeons` 非空时只处理单独副本。两份列表不应重复覆盖同一副本。

区域或副本不要求仍有红点；区域模式使用绿色副本名牌寻找入口，指定副本模式按完整名字定位，排除天星镇入口。支持从天星镇、区域图、大地图或副本面板开始，未选中区域的当前地图也会先返回大地图核对。

全部选定区域和指定副本处理完成后，通过大地图返回天星镇，确认抵达后再结束。达到 `max_dungeons` 的正常限额结束也会回城；返程沿用现有补点逻辑，回城失败会报错并保存现场。`summary.json` 的 `returned_to_town` 表示是否确认完成最终回城，最后截图也在回城后保存。

进入副本并切换英雄模式后，黄色“重置”按钮表示可以重置：点击重置，识别“提示”弹窗中的“确定”，等待英雄模式的“挑战”按钮出现，再照常挑战。灰色“重置”表示已经重置过，无论首次进入还是战斗失败后再次进入，都关闭面板并跳过当前副本，在 `summary.json` 的 `skipped` 中记录 `reason_code = "already_reset"`。跳过不会增加重置次数、钻石消耗或积分赛的三副本完成计数；本次运行也不再进入该副本。如果已经是可挑战状态，直接继续挑战。战斗失败后保留已完成关卡，重试时不会再次重置。

点击确认、补点、失败重试、领奖和每通关三个副本参加积分赛均沿用 `Daily_Hero`；积分赛回程后继续本区域，不重复处理本次已完成或已跳过的副本。通用参数默认继承 `[daily_hero]`，也可在 `[daily_hero_reset]` 中覆盖，例如 `max_dungeons = 1` 限制为一个副本。每次运行在 `artifacts/runs/Daily_Hero_Reset_时间戳/` 保存记录，`summary.json` 另含成功确认的重置次数 `resets`、已确认的钻石总消耗 `diamonds_spent` 和逐次明细 `diamond_spending`（区域、入口坐标、钻石数量）。每次运行从零计数，成功重置后才记一次；补点、战斗重试、灰色跳过和预演不增加消耗。后续战斗失败、运行报错或按 Ctrl+C 停止时，仍保存已确认的消耗；控制台也打印每次费用和本次累计。

图15、16及补充的真实重置确认弹窗均为 **1374×772**，比例接近16:9，可缩放到1920×1080与现有模板衔接；图15黄色重置可用，图16灰色重置不可用。确认弹窗要求同时识别重置专用正文，兼容三位数费用导致的正文换行，不能将积分赛的通用“提示”当成重置确认。当前费用模板支持真实截图中的 **钻石×10、钻石×50、钻石×300**，其中10钻同时使用莫鲁之地1920×1080原始PNG与缩放截图素材，300钻使用龙萌幻境真实失败画面；无法确认金额或补点前费用变化时停止，不猜测费用、不点击确定。识别费用前先保存无损的 `reset_序号_quote.png`，无法识别时也会保留；识别成功时另存 `reset_序号_quote.jpg`。成功重置后在 `events.jsonl` 的 `dungeon_reset` 记录本次与累计消耗。识别与统计已用原始PNG和JPEG回放验证，未向设备实际提交重置。

## check_arena：魔都擂主检查

```powershell
.\run_check_arena.ps1
# 只检查当前截图，不点击，也不修改配置：
.\run_check_arena.ps1 -Preview
# 或直接运行：
.\.venv\Scripts\python.exe -m pet_alliance run check_arena
```

从天星镇出发，进入冒险并通过大地图前往魔都。配置在 `automation.toml` 的 `[check_arena]`：

```toml
[check_arena]
arena_list = ["COCO号", "恶魔城", "鬼木断崖", "瘴气科研", "病态虫巢", "绝望监狱", "冥火特快", "死亡墓地", "永夜镇", "荒弃圣堂"]
player_name = "1111"
arena_expired_time = ""
arena_dungeon = ""
```

逐个按 `arena_list` 顺序检查绿色副本名牌下的擂主旗牌，不依赖红色感叹号。其他玩家占擂时直接检查下一个副本；空位或本人占擂时进入副本，点击右下“擂主”，在关卡守护神页面再次确认归属。期间归属变为他人则关闭并继续，未知或遮挡不当作空位。姓名按完整字形匹配；当前已采集本人 `1111`，改用其他名字需先增加姓名模板。

启动时打印实际生效的 `arena_list`，检查时逐项打印序号与跳过原因。地图上已经能判断为他人占擂的副本会直接跳过，因此屏幕上第一个点击进入的副本可能排在列表后面；完整检查顺序同时保存在运行报告的 `checked` 中。

- 确认无人：先检查该副本当天英雄级的五关“击败”印章，确认已经通关后才点击“挑战守护神”。独立 `check_arena` 不自动打英雄副本；未通关就跳过该候选，继续按列表检查。若出现“恭喜你成为新的关卡守护神！”提示，识别完整正文和提示标题后，点击下方空白关闭。新占擂的守护页面可能暂不显示姓名或时长，因此关闭提示后不依赖这两个字段：先关闭守护页面及副本页面，回到魔都区域地图，再检查**本次目标副本**的旗牌。本人旗牌才算占擂成功；他人旗牌继续下一个候选，未知或尚未刷新的空旗牌继续等待，超时则停止。成功提示和其他副本的本人旗牌都不能替代目标旗牌确认。提示关闭和两个页面关闭均支持重新识别后补点。

每次挑战补点前仍重新确认空位及当日英雄通关凭证。新占擂仅在区域地图确认本人后标记 `claimed`，并在运行报告记录首次实际发送挑战点击的北京时间 `claimed_at`；调度器据此加 **6 小时 1 分钟**保存新占擂期限，其中一分钟用于等待缓冲，避免读取未刷新的时长，也不会因补点推迟计算起点。新占分支的 `guard_seconds` 保持空值，不伪造 OCR 结果。原本已由本人守护的分支仍进入守护页读取真实已守护时长，计算准确的剩余期限。最后通过大地图返回天星镇。
- 确认本人已占擂：用本机 Windows 中文 OCR 读取“已守护时间”，按截图时记录的北京时间计算 `arena_expired_time = 当前时间 + 6小时 − 已守护时长`。支持小时、分钟、秒及跨日；超过六小时则保存过去的实际结束时刻。无法完整识别时不猜测、不改配置。保存成功后关闭页面并回城结束。
- 全部副本由他人占擂，或没有满足当天英雄通关条件的候选：先确认返回天星镇，再报错退出。调度器会把后者记为前置未满足，并按五分钟间隔重查。

结束时间保存为含日期和 `+08:00` 的 ISO8601 字符串，例如 `2026-11-06T04:42:02+08:00`，并保存对应副本 `arena_dungeon`。默认原子更新 `automation.local.toml` 的 `[check_arena]`，保留其他参数与注释；使用 `--config` 时更新所指定的配置文件。历史结束时间不会被当作本次检查结果，失败不会清空旧值。

截图17～20为 **1374×772**，可映射到1920×1080参考坐标。识别已覆盖魔都10个副本、图17的本人/他人/空位、图19无人和图20本人；图20实际 OCR 为 **19分58秒**。仅使用本机 OCR，无额外联网服务。导航、挑战、关闭与回城沿用 `daily_hero` 的截图和补点参数，可在 `[check_arena]` 单独覆盖。

每次运行在 `artifacts/runs/Check_Arena_时间戳/` 保存检查顺序、擂主归属、占擂确认、守护秒数、计算时刻、配置路径、回城结果和最后截图。预演、识别失败、报错和 Ctrl+C 停止均有独立状态；预演不会写配置。

## slay_dragon：屠龙托管监测与恢复

```powershell
.\run_slay_dragon.ps1
# 只检查当前截图，不点击、不重启：
.\run_slay_dragon.ps1 -Preview
# 或直接运行：
.\.venv\Scripts\python.exe -m pet_alliance run slay_dragon
```

启动时先读取电脑系统时钟的**北京时间（UTC+8）**，按时刻表判断是否处于屠龙时段：**09:00–11:00、12:00–16:00、18:00–22:00**，包含开始、不包含结束。

- 处于活动时段：已显示“停止托管”时直接开始监测；位于天星镇时，通过紫龙图标的红色眼睛锚点识别，从下面第3步直接进入屠龙战，省去重启和登录。
- 不在活动时段：先等待最近的下一次开场，到点从第1步执行完整重启恢复。等待前不操作游戏。

之后每轮监测后等待 **5 秒**。运行期间每轮开始、截图前后和每次点击或重启前都会重新检查北京时间；离开活动区间时暂停当前流程，等待下一场开场，再从第1步完整重启恢复。即使正在等待云散、进入游戏或准备补点，也会暂停并在下一场重新计算步骤超时。相邻的连续场次（例如20:00到21:00）保持正常监测。

看到“停止托管”保持不动；看到“开始托管”只点击一次，不立即确认或补点，下轮再检查。识别到天星镇（含登录通知覆盖的主城）时从第3步继续，其他未识别到托管按钮的页面按以下顺序恢复：

1. 只重启配置的游戏包，最多 **90 秒** 等待登录页“进入”。
2. 点击“进入”，最多 **90 秒** 等待天星镇；图11通知覆盖主城时也视为已到达。
3. 进入主城后，在同一个循环里优先处理右上角叉号关闭的“公告”页面，以及点击底部空白关闭的原通知；两类通知可任意顺序出现。没有通知时检测“屠龙战”文字，点击上方的紫龙图标。通知和入口检测共享 **5 分钟** 总超时，通知晚出现、再次弹出或云遮挡时都继续循环，直到确认进入屠龙战；切换检测目标不会重置计时，首次和补点均重新定位。
4. 每次重新定位“斯波纳克”再点击，直到名字被人物遮住且黄色感叹号出现；随后点击感叹号打开屠龙助手，回到监测循环。若助手已经打开，则直接继续监测。

按提供的时刻表，每日开场是 **09:00、10:00、12:00、13:00、14:00、15:00、18:00、19:00、20:00、21:00**，每场持续1小时，可在 `[slay_dragon].start_times` 修改开场列表。例如09:30启动后，会在11:00休场时等到12:00重启、16:00等到18:00重启、22:00等到次日09:00重启。控制台会打印计划开场日期与时间，等待期间按最多30秒分段重新读取系统时钟，支持系统校时、Ctrl+C和总运行时限；保持脚本运行即可到点执行。

恢复流程中的普通控件沿用 `daily_hero` 的截图间隔、最小点击间隔和补点设置，也可在 `[slay_dragon]` 单独覆盖。NPC 允许持续点击，但每次都重新识别并遵守点击间隔；靠近 NPC 和打开助手各受 `transition_timeout`（默认30秒）约束。未知通知不会被当作图11点击；超时或 ADB 错误会保存现场并停止。

参数在 `automation.toml` 的 `[slay_dragon]` 下。`package` 默认是本机已确认的 `com.monster.mxm1old`；通过 Android 启动入口重新启动游戏，不重启模拟器。`max_checks = 0`、`max_runtime = 0` 表示持续监测，按 **Ctrl+C** 停止；设为正数可限制监测次数或总运行秒数。每次运行在 `artifacts/runs/Slay_Dragon_时间戳/` 保存事件、检查/重启/开始托管次数和最后截图；`startup_schedule` 记录启动时间分支，`session_closed` 记录运行时跨入休场，报告的 `scheduled_waits` 与 `next_start` 记录等待次数和最近计划的开场时刻。

图8～13是完整的 **752×423、16:9** 游戏画面，无模拟器边框，可作为模板；识别坐标会映射到设备分辨率。素材及截图来源见 `assets/slay_dragon/README.md`。
