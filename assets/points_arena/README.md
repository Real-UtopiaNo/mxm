## 玩家白名单

当前完整名字模板是 **`Hello`、`Hell`、`coco`**，大小写敏感。只会选择同时出现在 `target_players` 和 `profile.json` 的 `players` 中的名字。识别校验完整名字的字数、字形、纵横比例、实际字号、相对高度、字符位置和间距；不会把 `Hell` 当成 `Hello` 的前缀，也不会将 `He llo` 或 `COCO` 分别当成 `Hello`、`coco`。未注册的配置名字没有视觉证据，会安全地返回找不到。

`target_players` 可以超过三项；每一场及每次补点都从列表第一项开始，选择当前画面可见且仍可挑战的最高优先级玩家。名单中的人可以中途加入、换格或重排，每帧都重新扫描**2行×4列全部八格**；`name_slots` 只描述网格位置，不绑定任何玩家。优先级最高的玩家仍可挑战时可以再次选择。每张入场券挑战三场，结算后回报名页重新截图读取票数，有票则再参加，确认 **0/5** 后才退出积分战；诊断图片和事件按报名轮次 `entry` 区分。没有名单目标时仅等待，到 `transition_timeout` 仍无目标才停止。

`native_after_hell.jpg` 和 `native_after_hello_coco.jpg` 是两次真实停止截图。旧版849像素整词匹配在第一张图漏掉Hello/coco，在第二张图漏掉换格后的Hell：1像素的细笔画变化会移动后续字符的位置，导致整词重叠分数失真。现在改用高分辨率姓名及完整字符布局校验，并为三个名字保存实际原生字形。回归将真实整张选手卡搬到全部八格、跨三种分辨率验证；覆盖动态加入、跨行重排，以及补点前旧位置被陌生玩家占据的情况。

可挑战卡片还必须保留头像左侧完整的橙色边缘；结果印章遮挡此边缘时，即使名字完整也不会再选。守卫已用真实胜利卡片和白、蓝、红合成遮挡验证；目前没有真实败北卡片截图，不将合成验证视作实战败北验证。

增加目标名字时，除修改 `automation.toml`，还需要在目标列表页采集该名字的模板：

1. 优先取得原生ADB 16:9 PNG，不能包含模拟器工具栏。经 `VisualFrame` 归一到1920×1080，从该高分辨率画面采集名字；不要先调用 `_image()` 把姓名缩小到849宽度。
2. 从名字条内侧裁取完整文字及两侧空白。`name_slots` 的坐标基准仍为849×477，4列起点x=292、398、505、611，两行起点y=201、340，区域大小76×14；裁高分辨率画面前，x和宽度乘1920/849，y和高度乘1080/477，并对裁剪边界四舍五入。名字若超出该范围、被遮挡或被截断，应重新采集，不要裁出某个前缀。
3. 用 `dark = patch.max(axis=2) < 145` 和 `neutral = patch.max(axis=2).astype(int) - patch.min(axis=2) < 55`，取 `(dark & neutral).astype(np.uint8) * 255` 获取深色字形并排除棕色名牌边框，裁掉四周空白，保存为灰度PNG，例如 `player_NewName.png`。
4. 在 `profile.json` 的 `players` 对象增加 `"NewName": {"file": "player_NewName.png", "source_size": [1920, 1080]}`。配置和这里的名字必须完全一致。不同截图的笔画渲染存在差异时，可以在 `player_variants` 增加 `"NewName": [{"file": "player_NewName_native.png", "source_size": [1920, 1080]}]`；每个变体都必须来自该完整名字的实际画面。`source_size` 是裁取名字前整张识别画面的尺寸，不是裁片尺寸；旧式纯文件名条目默认使用849×477坐标系。再加含此名字的回归截图，确认八个格子中正确名字都成功、近似名字和大小写变化均拒绝。

名单布局发生变化时需要重新校准 `name_slots`；当前实现覆盖图6的4列×2行全部8个位置。异常画面、未知票数或无匹配白名单均应由工作流保存截图并停止。
