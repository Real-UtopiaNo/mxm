用户提供的图 15、16 及真实重置确认弹窗均为 **1374×772**，包含完整游戏画面，没有模拟器标题栏或侧边栏。宽高比约 1.7798，与 16:9 相差约 0.002，可由现有 `VisualFrame` 统一到 1920×1080，并在点击前换回设备坐标。原图保存在 `tests/fixtures/daily_hero_reset/`，真实弹窗为 `reset_confirm.png`，运行不依赖 `artifacts/temp/`。

`reset.png` 来自图 15 的黄色可用重置按钮；`reset_disabled.png` 来自图 16 的灰色重置按钮，表示已经重置过。首次进入或失败后重新进入只要识别到灰色重置，都关闭面板并跳过该副本。二者要求现有英雄龙图标和副本面板叉同时存在，不能在普通模式或未知页面操作。颜色误差检查将灰色按钮和暗化的底层按钮排除。

`cleared_stamp.png` 取自图15的红色“击败”印章文字，供占擂前核验英雄通关使用。`HeroResetVision.hero_state(frame)` 先确认活跃的英雄面板，再分别检查 `hero_clear_slots` 的五个关卡槽位；五处全部命中才返回 `cleared`。有“挑战”且未确认五关全部通过时返回 `incomplete`，其余情况返回 `None`。不能仅凭黄色或灰色重置按钮推断已通关，也不能在这里点击重置。已用图15/16、未完成及部分完成截图验证四种分辨率，并验证逐槽遮挡、去色、普通模式和弹窗负例。

`confirm_reset.png`、`reset_dialog.png` 使用真实重置弹窗的“确定”按钮及“提示”标题。确认还必须同时匹配 `reset_dialog_action.png`（“刷新当前英雄关卡需要”）与一份完整的刷新进度询问及每日一次限制正文；`reset_dialog_bodies` 列出原排版 `reset_dialog_body.png` 和换行排版 `reset_dialog_body_wrapped.png`。因此积分赛的普通提示不会被当作重置确认。这些正文锚点独立于金额，费用无法读取时仍能识别重置弹窗，并由调用方停止确认。

`reset_cost_10.png`、`reset_cost_50.png`、`reset_cost_300.png` 分别精确匹配真实弹窗的黄色 `x10`、`x50`、`x300`，已知费用及其末尾检查范围写在 `profile.json` 的 `reset_costs`。`HeroResetVision.reset_cost(frame)` 只在完整重置正文存在、金额模板吻合且末尾没有额外黄色数字时返回对应整数，否则返回 `None`；没有使用猜测金额或未经验证的 OCR。末尾检查防止将 `x100`、`x500`、`x3000` 的前缀当成较小金额。调用方必须在确认点击前检查本帧的费用，不能仅凭找到“确定”按钮提交。

`reset_confirm_10.jpg` 来自 `Daily_Hero_Reset_20261106_025714_548654/last_frame.jpg`，是莫鲁之地的真实 1920×1080、10 钻石报价。金额模板取该图经 1280×720 缩放后统一回参考坐标的 `[1099,491,1165,530]`，使字体抗锯齿同时适配四种截图尺寸，仍保留 0.94 的金额匹配阈值。真实截图缩小至 849×477 后，两段正文锚点的相关性约 0.91，因此正文阈值调整为 0.90；标题、两段正文必须同时匹配，颜色误差上限仍为 18。原始失败截图的正文、标题和确定按钮本来均能识别，退出的直接原因是此前只配置了 50 钻石金额。

`reset_confirm_10_raw.png` 是 `Daily_Hero_Reset_20261106_055750_183733` 停止于莫鲁之地重置报价后，通过只读 ADB 截图采集的 **1920×1080 原始 PNG**。此前只验证日志 JPEG，平滑模板对原始 PNG 的相关性为 0.939235，低于 0.94，而保存后的 JPEG 可达 0.954807，掩盖了实际运行问题。新增 `reset_cost_10_native.png` 直接裁取原始 PNG 的 `[1099,491,1165,530]`，与原平滑模板并列支持同一金额；匹配阈值、颜色误差及额外数字检查不变。必须同时保留原始 PNG 和 JPEG 的四分辨率回放，不能仅凭压缩后的诊断图验证实时识别。
